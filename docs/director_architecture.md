# Banana MV：原始拍法與獨立分段

給故事大綱、歌曲與參考圖，沿著主軸拍音樂 MV。保留人物分工、因果、轉折和指定結果；用演唱、故事、反應、細節與環境交錯呈現，不要求每個十秒都演完一場完整短劇。

## 導演與切鏡

全曲導演沿用最初 `b797c7e` 的 prompt-only 導演風格：使用當段模式、原本強度描述，以及「事件 → 行動 → 注意力 → 攝影 → 剪輯」。約 3–5 秒切鏡採用當時原文：

> Use motivated editorial cuts and distinct camera compositions around 3–5 seconds where possible; short transition shots may appear anywhere. Cuts are flexible, not fixed to segment boundaries.

這是攝影節奏指引，不是最低鏡數。不再計算 required_shots、不因單鏡而重試、不按字詞或固定寬中近模板補鏡。關閉動態切鏡時偏向長鏡；最後畫面停留時不引入新動作。主唱可見時採半身或更近，並遵守指定演唱角色。

全曲導演保留一次規劃，FREE 可濃縮次要情節並設計相容的演唱／故事穿插；FAITHFUL 保留原事件順序。兩者都守住角色、獨立場地、因果與指定結果。音樂資料提供節奏與強弱參考，不假裝辨識未提供的歌詞或副歌。沒有固定演唱占比，也不照每句歌詞發明新事件。

## 一次交稿與段落隔離

新任務預設 director_schema=4、scene_state_version=0。全曲導演一次整理故事、分配各段事件，直接交付每段可送 H3 的簡潔拍攝提示詞。各段稿只包含當段拍攝內容、當下角色外觀、道具、場地、鏡頭、演唱分工與適用的收尾要求，不包含前段故事回顧。下游不讀整份大綱，也不再呼叫 9B。回到同一場地／主唱可換拍法，不重演先前事件。

角色只在分配到的段落出場，原始 Picture N 不因角色退場重新編號。末幀接續時，上游已知後續各段圖片編號的偏移，Picture 1 留給實際取得的前段末幀。所有鏡頭時間為當段本地時間。

## 交稿、生成與續跑

正常流程只有一次上游模型呼叫。導演交稿後，全部段落提示詞立即保存並可在前端查看。下游只裁音訊、接圖片、套生成設定、送 H3 拍攝，最後合成；不要求 shot-only 輸出、不拆六段重組、不點名角色、不檢查切鏡數、括號或時間標記寫法。

上游直接交最終稿，以 `=== CLIP 0 action ===` 等行標示段落，最後以 `=== END ===` 表示交稿完成。提示詞本身保留原文，不需把引號、換行或大括號轉成 JSON 字串。程式只讀段落邊界，不拆解或改寫鏡頭。仍可讀取既有 JSON 交稿，正常新交稿不再要求巨型 JSON、六段式重複格式或結尾狀態物件，也不附加整份單片改寫指南。

SRT 先按實際來源區間分配，再轉成本段時間送給上游，避免時間錨點混用。每段的收尾開始及停留時限由程式換算後提供，讓導演在稿內安排結局。重試只給簡短的交稿錯誤，不把數萬字失敗分析再塞回輸入。

只檢查上游是否交齊各段非空提示詞、媒體引用是否已連接，以及整份交稿是否有結束標記。多圖稿必須至少明確綁定原始 Picture 編號，無任何綁圖的純故事翻譯不送 GPU；不要求所有角色出場，也不檢查鏡號或括號。前端預設顯示圖片1–9獨立欄位，每格只選一張；清除不遞補，中間有空格則先補齊再送出，末尾可留空。接續版停用第9格。控制詞編號須與欄位一致，程式不按外觀猜測並重排角色。開啟舊專案可查看保存的各格圖片，續跑沿用原素材。缺段或空稿使用既有限次重試，不另外開語意審查。提示詞字數預算依段數與既有 9B 輸出上限分配，不增加模型或生成次數。長歌一次交稿的實際品質與輸出上限仍需 GPU 實測。

逐段生成、失敗續跑與丹藥回爐都沿用保存的當段提示詞。已完成的影片不重跑，後續段落不重新解讀先前故事。舊專案保留原來儲存的流程；新建任務才採用新版交稿方式。

原曲、24fps、影格切段、H3 採樣、注意力、LoRA、Seed 和丹藥檢查／回爐流程均沿用既有設定。生成時保留音訊對嘴驅動，毛片預覽無聲，完整合成混入原曲。

## 整首與片段

- full：程式提前預留收束窗口及末尾停留時間，以每段 ending 欄位提供；導演在對應提示詞完成事件並保持結尾畫面。短尾段不臨時開新場景。
- excerpt：段落可以完成局部事件，不硬製造整首勝利、謝幕或淡出。

新版純文字交稿不要求模型另寫 ending_plan，避免同一件收尾工作又輸出第二份狀態資料。保存的 director_plan.json 仍由 Python 產生，用於快取與續跑；這不等於要求模型生成 JSON。舊版 JSON／狀態計畫依保存格式相容，損壞快取不會偷偷重寫。

## 驗證範圍

測試覆蓋原始切鏡文字、單鏡不觸發湊數重試、當段隔離、固定原圖編號、角色交接、完整／片段結尾、壞快取拒絕、原曲路由及失敗續跑。測試使用模擬模型與 GPU；不代表已用真實 9B／H3 重現早期畫面品質。更新程式並重啟服務後，新建任務比較；已保存 prompt 不會自動重寫。
