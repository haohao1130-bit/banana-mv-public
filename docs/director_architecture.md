# 自由導演整合：單一全曲計畫

此版已同步統一導演流程。新任務保存 `director_schema=3`；既有任務不升級、不重排已完成影片，仍使用其原版本流程。這是既有 `ensure_plan → worker → local_prompt → scene_state` 呼叫鏈的新資料版本，不是第二個同時指揮影片的導演。

## 根因與處理

舊資料顯示：文字清單被分組濃縮後反覆重演同一事件、遺失尾聲；當段模型再次看到整份故事而重新開場；正文已發生服裝變化，帳本卻沒有 deltas，後續重複穿脫並卡在依賴條件。額外 appended guidance 又把導演管理文字和畫面描述混在一起。

先前第一階段已修服裝類別鍵到明確 ID 的正規化與分段進展檢查。這一階段讓新任務從資料流上共用一份權威計畫，不再把全曲計畫交給另一個初始化推論重新解釋。

## 新舊資料流

舊：故事 → 事件提取 → 局部濃縮/補格 → 另外推論狀態事件帳本 → 每段讀整份故事、寫畫面及 JSON → 必要時再推論記憶 → 追加多套規則 → H3。

新：故事/參考圖/歌曲資訊 → 一次整曲創作計畫 → Python 驗證/編譯初態、事件及各段必要變化 → 逐段只寫畫面 → H3 → 成功保存後提交同一份計畫的變化。

正常情況為1次全曲規劃 + N次當段畫面改寫；沒有另外的狀態初始化或記憶推論。修復僅在結構、引用、連續性不合法時使用設定內的預算；相同失敗不無限重試。沒有新增語意審核模型。

## 創作權限

自由導演：原故事是素材，可以合理擴寫、刪減、重組與交錯演唱/故事；保留明確硬限制與角色分工。忠於劇本：維持原事件意義及順序，安排動作與攝影。影片風格仍保留自動、演唱、舞蹈、武打等所有原選項；風格是偏好，不能將原本分離的演唱與戰鬥混成同一世界。

不固定演唱比例、切鏡間隔或分鏡模板；不強迫每段新增重要事件或完成全部故事事件。未完成動作可以延續，可重複的表演可以返回。完成的一次性事件不能重新執行。高潮可以早於最後一段；`closing_shot` 明確安排歌曲結束的最後畫面，可為演唱、餘韻或刻意未解決的畫面，不強迫勝利/大團圓。

## 模組職責

- `story_plan.py`：單次整曲創作、修復與快取。事件用局部索引表達，Python 產生穩定 E1/E2 ID。規劃包含必要的初態、角色/場景限制、事件、各區間畫面任務、完成進度、狀態變化及最後畫面。規劃時即演算整條狀態鏈，錯誤在 GPU 開始前提出。
- `scene_state.py`：沿用既有帳本、驗證、快照與提交機制。`ledger_from_direction` 從已保存計畫建立帳本，不呼叫模型；`compile_direction_record` 根據繼承狀態計算 from 和 ID，再經完整 `plan_clip` 驗證。宣告需改變狀態的事件不能靠空陣列或無效變化假裝完成。
- `prompt_quality.py`：當段只收到畫面任務、必要角色限制、目前/預期外觀與少量音樂時機資訊，不重送整份故事、事件 catalogue 或操作權限。輸出為純 H3 畫面文字，不讓當段模型填寫狀態 JSON。Python 仍保存完整內部資料。
- `server.py`：新請求選用新資料版本；串接同一計畫與帳本。影片保存成功才提交變化。沒有更動音訊切片、影格、採樣、LoRA、注意力、Seed、下載、裁切或合成演算法。
- `web/index.html`：保留原控制項及數值，只說清楚「影片風格」與「自由導演/忠於劇本」；不再聲稱新任務要多一次狀態初始化。

角色參考不假設圖一是成年女性。場景參考不建立假人物；同一人物的多視圖不必建立多個人。Face Lock 使用原函式，但綁到計畫中 S1 實際指定的原圖，包括圖一是場景、圖二才是人物的情況。非人角色保留原身分及形態。末幀接續仍將圖號位移一格，上一段末幀不是新角色。

## 驗收與限制

新增測試覆蓋全曲狀態鏈、缺少變化不能宣告完成、中間服裝狀態、一次性事件重播、未授權重穿、未完成動作延續、高潮後尾聲、平行場景、非人角色、圖一為場景、單段歌曲、忠於劇本、計畫修復/快取、提示詞膨脹，以及兩種分段模式中途失敗與續跑。既有 HTTP/媒體整合測試仍執行。

來源版本驗證記錄：私人版 Python 全套149 tests，OK；其中新流程14項測試包含 mock worker 的獨立分段/末幀接續失敗續跑。Node 前端測試與 `git diff --check` 通過。真實9B推論、Colab GPU影片以及新任務環境還原未驗證。

計畫與記憶描述的是預計生成的內容，沒有影片視覺辨識。9B仍需產生一次合法的整曲結構，且可能誤解故事、漏寫需求或把非重複事件錯標成可重複。Python驗證不會保證語意創意或影片物理正確，也不會用服裝關鍵字猜測使用者意圖。當段模型仍可能不遵守畫面任務，需要真9B與Colab GPU對照評估。

模型呼叫仍透過既有可設定的 rewriter 與 callable 介面；本次未下載27B、未改聊天模板/載入器，未宣稱Gemma可直接替換現有Comfy節點。未來模型載入/顯存方案需獨立評估。

## 載入與既有作品

只有本地 Git 提交不會更新使用者 Colab。取得新私人版程式後，重啟 Banana MV Python 服務或使用新 Colab 執行階段，並建立新專案，才會使用新資料版本。重跑舊專案會保留舊計畫、提示詞與已完成影片，不能拿來驗證新導演流程。公開版已同步功能；回歸素材及新增專用測試仍留在私人版。
