# Banana MV：單次編排與逐段拍攝

目標：給定故事大綱、角色參考和歌曲，沿著人物目標、因果、主要轉折與指定結果，拍出有張力的 MV。電影導演可濃縮次要事件並設計相容的動作、走位、反應、攝影與剪輯；忠於劇本模式另保留原事件順序。兩者都保留角色分工與獨立場地。

## 獨立分鏡預設（2026-11-06）

新任務預設**全曲一次規劃、各段獨立寫鏡頭**。全曲 9B 先決定各段的獨立現場命令 `segment.event`、`subjects`、`appearance_in/out`；分段 9B 只根據該段 `visual_task`、當段出場角色及當下外觀編排攝影，不接收歷史事件與完成事件流水帳。若主角在第一段完成變身，後段 `subjects` 只列變身後角色，除非劇本明確安排變回來。後段服裝只描述**目前穿著**，歷史上已脫下的衣物不被重列，除非當段有意讓它作為道具出鏡。

原始圖片仍按原本上傳順序提供作為引用資產；當段的固定角色表只包含正在出場的角色，其他圖片不能自動創造額外人物。歷史狀態機仍可以手動選用，但新任務預設關閉；舊專案的 `scene_state_version` 仍依保存設定復原。這些規則減少重演誘因，不等於具備理解影片的語意驗證能力；仍需核對全曲 9B 初始分段是否把事件／角色分配正確。

## 流程與責任

正常模型呼叫是 **1 次全曲規劃 + N 次分段畫面寫作**。移除固定的全曲及逐段第二次語意審查。新任務記錄 prompt_compiler_version=1。Python 處理區間時間、角色參考圖綁定、事件依賴與完成進度、狀態變化、終局保留和格式；格式或明確引用錯誤才在原有限預算內重試，相同失敗不無限循環。

全曲模型收到一次大綱、原始參考圖、時間線與精簡 JSON 契約，產出初態、必要限制、里程碑、各段事件與收束安排。事件與影片區間數分開，一個事件可跨段但只能完成一次。普通演唱與鏡頭移動不必產生狀態變化。

新計畫每段明列 subjects 入鏡角色，包含不唱歌的故事角色；空清單表示無固定角色。當所有入鏡角色都有已知場景時，只傳入相關環境；場景不確定或空景時保留環境資料，不猜測圖片角色。當段模型只收到核准事件、當前外觀、必要限制、參考圖對應、一種主要拍法、局部音樂資訊及適用的收尾要求。外觀有變化才附預期外觀，不重送整份故事或完整帳本。新版不再每段載入完整外部指南，改用專用短 system；原指南及舊路徑留給相容舊任務。新寫手只回傳帶切鏡標記的英文畫面描述，程式組裝固定六段結構、角色綁定、當前外觀、實際出場標記和原音訊。聲音欄位不交由模型改寫，不自動補入歌詞。專用改寫模型若仍回傳原生六段格式，先驗證並只取畫面區塊，其餘模型 metadata 丟棄後由程式重建，不為格式習慣額外多叫一次模型。

攝影按「事件 → 行動 → 注意力 → 鏡頭 → 剪輯」；只選當段適用的 recipe。最後畫面停留時不再要求新攻防或新高潮。動態切鏡由動作與音樂決定；關閉時偏向連續長鏡。

## H3 原生格式

精簡的是管理文字，保留 Ref2VA 官方六段順序：subject_definitions、summary、retention_analysis、detailed_description、overall_soundscape、non_diegetic_music。第一鏡使用 [Shot 1]，後續切鏡使用 [Shot N] At MM:SS.mmm。參考標籤跨區一致，只有實際使用的參考需列入；完整原曲使用 fully_copy，不額外編曲或加入聲音。

角色 S1/S2 對應 Subject ID；語音來源 (Sx) 是另一套編號。程式驗證六段欄位順序、非空內容與明確的 Subject/Picture 宣告是否違反指定綁定。新寫手另檢查鏡號連續、第一鏡無時間、後續時間遞增且小於可見秒數、各鏡有描述、入鏡 Subject 與當段角色一致。這些是技術檢查，不能從普通文字判斷所有動作或勝負；不新增語意審查呼叫。

## 整首與片段

新任務保存 project_scope=full 或 excerpt，不依音檔長度猜測。

- excerpt：closing_shot 為空、ending_plan=null；最後區間停在可接續的節拍，不製造全片終局。已分配的局部事件仍可有結果。
- full：ending_plan 提供 start_time、resolved_by、resolution。至少預留最後一個正常區間收束，不足半段的短尾段與前段一起完成。例如 72 秒、10 秒分段，最晚 60 秒開始；複雜結局可更早。必要動作完成後保留最多 1.5 秒終鏡停留。受影響段落要具體寫完成動作、結果成立、抵達最後姿勢/構圖/光線的過程，不能只用一個切鏡代替故事收束。

未改動原曲、影片影格切法、H3 採樣、注意力、LoRA、Seed、下載或合成。不用黑畫面或自動淡出冒充結尾。影片保存有效後才提交預計狀態；visual_verified 不因此變為 true。

## 相容性與驗證

未帶 prompt_compiler_version 的已存專案沿用舊寫手、fingerprint 與快取，已完成影片不重排。新計畫的 fingerprint 包含編譯器版本，避免新舊寫手契約混用。更新程式並重啟服務後，新建任務驗證新寫法；舊任務續跑可沿用已保存的 prompt。

測試涵蓋一加 N 次呼叫、獨立與末幀接續、失敗續跑、角色引用修復、無效格式不標成功、狀態變化、事件不重播、六段指令契約、外觀去重、整首收束與片段延續。測試使用模擬 9B/H3；沒有實際 GPU 速度、顯存或畫質驗證。移除語意審查後，technical_only 只表示技術檢查通過，不保證模型遵守所有敘事要求。

本輪驗證：186 項 Python 測試與 Node 前端功能檢查通過。獨立分段/末幀接續的 worker 續跑測試同時覆蓋新舊寫手，正常皆維持一次計畫加 N 次寫手；失敗下載不重寫已完成片段。新畫面寫手的固定 system 為 1,640 字元，舊六段寫手為 2,347 字元；不含任務資料。字元數不是 token 數，也不是 GPU 顯存或實際推論耗時。

結尾將 ending_plan.resolved_by 轉成當段 local_resolution_by，與最終畫面開始停留的 local_settle_by 分開。前者為零表示故事主軸已完成，當段應拍餘韻而非重演。末幀接續的 previous_last_frame 明確只作為開場幀。

## 前端操作

專案操作按鈕使用等寬分組與固定間距；選取專案和開啟按鈕在手機窄螢幕上下排列；續跑、停止使用整列按鈕；操作按鈕最小高度 44px，保留 hidden 與 disabled 的原有行為。前端功能測試通過；此次環境禁止本機 Chromium 建立所需 socket，未完成實際瀏覽器視覺驗收。

## 借鏡與限制

借鏡開源專案的責任切分、全曲短綱、終點畫面與明確參考路由，未複製其實作，也未加入額外逐鏡生圖、動作控制影片或全曲修復代理。專用 H3 量化改寫模型對「只寫畫面描述」的新契約仍需 Colab 實測，不把一般 Qwen 9B 的案例當作效果保證。

高動態手腳缺失與模糊屬於實際影片品質問題，這次格式編譯不宣稱可修復。可另外評估動作參考或 ComfyUI-MAINodes Motion Lab 的局部重生成；在測得原音訊、角色、動作、耗時與顯存之前，不直接套到每段生成，也不改既有採樣/注意力/LoRA 參數。
